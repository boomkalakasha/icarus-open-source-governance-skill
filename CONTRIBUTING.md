# Contributing

Thank you for improving reusable, evidence-led open-source governance.

## Before a pull request

1. Work on a focused branch; do not push directly to `main`.
2. Use a truthful Conventional Commit subject such as `feat(scanner): add a tested marker rule`.
3. Keep English and Chinese behaviorally aligned when public behavior changes.
4. Add a discriminating test for scanner, validator, package, or eval behavior.
5. Run the local checks documented in the README and include their fresh output in the pull request.

Do not submit credentials, private hostnames, customer data, copied policy text, unproven rights claims, or personal branding as a mandatory default. Report security-sensitive material through [SECURITY.md](SECURITY.md), not a public issue.
